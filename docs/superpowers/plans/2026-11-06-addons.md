# Add-ons: a plan

**Goal.** Add a list of optional features, called add-ons, that the player can switch on and off from a page in the game. This gives the owners a safe place for experiments and for ideas that do not fit the main game. When an add-on is off, the game behaves exactly as it does today.

**Status.** The system (steps 1, 2, 4, 5 and 6) is built, with no add-ons yet. Runs with add-ons on count as usual and say so in the HUD and the run report; the page is open from the start and ships on the website too. Step 3 (the first add-ons) waits for the owners.

## How it works

1. **Registry: `js/core/10b-addons.js`, a new file loaded right after `10-settings.js`.**
   - It defines `ADDONS`, the list of registered add-ons.
   - `addonRegister(def)` adds an entry.
   - `addonOn(id)` returns true when the add-on is on.
   - `addonSet(id, on)` switches it, saves, and calls the add-on's own `on()` or `off()` hook.
   - Each entry looks like this:
     ```js
     { id:'bighead', name:'Big Heads', desc:'Every creature gets a huge head.',
       tag:'experimental' | 'extra' | 'silly', def:false,
       when:'any' | 'between-runs',    // whether it can change during a run or only from the menu
       fair:true,                      // false: runs with it on are marked in the run report (see questions 2 and 3)
       needs:function(){ return true; },// optional unlock rule, such as a chapter reached
       on:function(){}, off:function(){} }
     ```
2. **One file for each add-on**, under `js/addons/` (for example `50a-addon-bighead.js`).
   - Each file goes in `index.html` after everything it wraps, and before `45-test-exports.js`.
   - It registers itself and changes the game only through wrappers that check the switch on every call:
     ```js
     const base = enemyDraw;
     enemyDraw = function(){ if (!addonOn('bighead')) return base.apply(this, arguments); /* ...the add-on's version... */ };
     ```
   - When the add-on is off, the wrapper passes straight through to the original function, so turning it off is safe.
   - No add-on file may edit a core file directly. Taking an add-on out of the game means deleting its file and its `<script>` line.
3. **Save.**
   - Add a new field `addons: {}` to `DEFAULT_SAVE`.
   - `Save.load` keeps only entries whose id matches `/^[a-z0-9]{1,24}$/` and whose value is `0` or `1`.
   - It does not drop ids it does not recognise, so loading an older build of the game does not wipe the choices.
   - Add `addons` to the list of fields `Save.reset` keeps, because add-ons count as the player's settings.
   - Old saves load as "all add-ons at their default". `gear-oldsave` and `oldsave-deep` already check that old saves load.
4. **Add-ons page.**
   - A new "Add-ons" button sits next to Settings on the main menu, and the pause menu gets a short version of the same list.
   - Each add-on shows as a card with:
     - its name and description
     - a tag badge (Experimental, Extra or Silly)
     - an on/off toggle
     - "Takes effect next run" when `when` is `between-runs`
     - a lock with its unlock rule when `needs()` is false
   - There is a "Turn all off" button at the bottom.
   - The page is built from `ADDONS`, so a new add-on appears there without any change to the page.
   - It must work at 1280×720 with no scrolling for up to about 8 add-ons, and on a phone in both orientations.
5. **Visible state.**
   - While any add-on is on, the HUD shows a small "+N add-ons" chip in a corner, so screenshots and bug reports show it.
   - The run report lists the add-ons that were on.
6. **Developer add-ons.**
   - An add-on with `dev:true` appears only when the dev panel is loaded or the URL has `?addons=all`.
   - Unfinished ideas can be committed this way without players seeing them.
   - The website package keeps shipping every non-dev add-on. `45b-dev-panel.js` stays out of the build, as it is today.
7. **What stays as it is.**
   - The Lovable `GR` export/save bridge does not change. Add-on choices travel inside the normal save.

## Steps (one branch, `claude/addons`)

1. Registry, save field, sanitizer and the keep-on-erase entry. Add `addons` to `DEFAULT_SAVE` and `Save.load`.
2. The Add-ons page, the menu button, the pause list, the HUD chip and the run-report line.
3. Two starter add-ons to prove the system works. One should change during a run (a visual one) and one should change only between runs (a rule change). The owners pick them from the list below.
4. A scenario, `tools/scenarios/addons.js`, added to `ci-check.sh`. It checks that:
   - every registered add-on switches on and off ten times with no errors;
   - with everything off, a seeded 600-step run ends in the same state (score, position, enemy count) as a run without the add-on scripts;
   - the save survives a round trip and old saves load;
   - unknown ids are kept;
   - the page draws on desktop and on a phone.
5. Docs:
   - README file-map rows, a `lovable.md` row for each file, a `QA-GUIDE.md` line, and the recount and gallery sync.
   - A short "How to write an add-on" section in `AGENTS.md`: one file, wrappers that check `addonOn`, no direct edits to core files, and a line in the scenario.
6. Screenshots on desktop and phone, CI, then a PR that waits for "merge".

## Starter add-on ideas (pick any)

1. **Big Heads** (silly): creatures and the giraffe are drawn with oversized heads. Visual only.
2. **Damage numbers** (extra): floating numbers when a hit lands, coloured for crits.
3. **Chaos waves** (experimental): each wave rolls one random modifier, such as fast enemies, double gold, low gravity for kicked enemies, or a fog wave.
4. **Retro filter** (silly): a pixelated look with a smaller palette, drawn over the canvas.
5. **Endless mode** (extra): after a chapter's last wave, waves keep coming with rising difficulty; best wave is stored per chapter.
6. **Pacifist challenge** (experimental): no kicking, and she only wins by dodging and luring enemies into each other or the scenery.
7. **Pet companion** (extra): a small bird that follows her and pecks at the nearest enemy.
8. **Mirror world** (silly): the map is flipped left to right.
9. **Speedrun timer** (extra): a split timer for each wave, with personal bests.
10. **Ragdoll kicks** (silly): kicked enemies tumble and bounce off walls before they vanish.

3. Should `fair:false` add-ons be marked, as in the second answer to question 2, or blocked from earning rewards?
